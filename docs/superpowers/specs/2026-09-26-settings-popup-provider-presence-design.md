# 设置、Popup 与提供商实例设计说明

## 目标与现状

设置界面改为三列，popup 保持两列并持续展示所有已启用提供商的摘要。每个提供商可独立决定是否占用 macOS 菜单栏或 Windows 任务栏；无原生实例的已启用提供商降低自动刷新频率。

当前 popup 已有宽 92px 的 `ProviderRail`，但右侧会按选中项筛选现有 `Dashboard`。通用设置、提供商列表和详情分属不同页面。Tauri 主窗口固定为 440 逻辑像素宽。`ProviderLayout.enabled` 和 `taskbandProviders[id].enabled` 本来就是独立状态，缺少后者时默认开启。原生实例当前依赖可渲染的固定指标，暂时无快照时可能消失。Rust 目前每 5 分钟整批刷新所有已启用提供商，10 分钟后标记快照过期。

macOS 目前存在 Quota01 应用菜单栏图标和强制兜底，Windows 存在应用级托盘图标。本设计取代先前的 macOS 应用图标方案。Linux 现有托盘模式不在本次 macOS/Windows 提供商实例改动范围内。

## 设置工作区

**窗口隔离约束：**设置工作区和提供商 popup 必须是两个独立的原生窗口。Popup 窗口固定 440px 且只显示数据；popup 中的设置入口打开独立设置窗口，不能把 SettingsWorkspace 路由进 popup。主窗口始终停留在 popup 页面；Settings 窗口始终停留在三列工作区，原生提供商菜单只改变工作区内的选中项，不做页面跳转，也不显示页面返回按钮。打开设置时收起 always-on-top popup；关闭设置后在仍有提供商原生实例时恢复 popup。设置窗口按当前显示器工作区限制尺寸。

- 左列显示全部已知提供商的图标、名称、启用状态和原生实例状态。点击行仅改变选择，不自动启用。左列另有“通用设置”入口。
- 中列显示选中提供商的现有设置，包括命名、登录、指标、固定指标、排序和平台专属实例样式；选择“通用设置”时显示现有通用设置。
- 右列复用 popup 的单提供商数据组件，实时显示选中项的读数、加载、错误、空状态与手动刷新。“通用设置”对应应用级说明，不残留旧提供商数据。
- 数据变化时保持选择。选中项消失后优先选第一个已启用提供商，再选第一个可用提供商。窗口目标宽约 1000px，并限制在当前显示器工作区内；宽度不足时改为左侧列表与设置/预览切换面板。返回 popup 时恢复 440px。

## Popup

Popup 与设置窗口相互独立。切换到设置不能改变 popup 窗口的宽度，也不能在 popup WebView 中渲染设置内容。

- 左列按设置顺序常驻显示**所有已启用提供商**，包括已关闭自己原生实例的提供商。每行包括图标、可读名称，以及最多两个固定指标的简要读数；缺失读数显示稳定占位。
- 右列只显示当前提供商的完整数据。点击哪个原生提供商实例，就选中哪个。通过快捷键或直接打开应用时，恢复有效的上次选择；否则选第一个已启用提供商。切换右列不隐藏左列其他摘要。
- 没有已启用提供商时展示可操作的空状态。保留现有刷新、错误恢复、分享和数据自定义入口。

## 原生实例与退出

- 开启提供商时，自己的菜单栏/任务栏实例默认开启。单独关闭实例不关闭提供商，该提供商仍在 popup 中并继续后台刷新。明确关闭的状态跨重启和自动检测保留。
- 有效实例要求提供商已启用、实例布局已启用、定义存在且至少配置一个可固定指标。读数暂不可用时原生实例显示 `--`，不能因为短暂 API 错误而消失。没有固定指标时解释无法显示的原因。退出判断使用**实际创建成功**的提供商实例数。
- 最少一个实例只计算提供商实例。移除 macOS 和 Windows 的 Quota01 应用级图标、相关设置及强制兜底。若没有提供商实例，启动时直接打开设置，运行时保持设置窗口可见。离开设置时确认“应用将退出”；取消留在设置，确认等待尚未完成的保存后退出。
- Escape、标题栏关闭、系统窗口关闭、点击窗口外、快捷键和跳转 popup 都走同一退出判断。设置页不提供页面返回按钮。明确的“退出应用”命令直接执行。每个提供商原生实例的右键菜单仍有“设置”和“退出”；“设置”选中该提供商。创建实例失败时显示错误，并保持设置窗口可用。
- Linux 暂时保持现有托盘模式，因为本次不新增 Linux 单提供商实例。

## 刷新频率

| 状态                       | 自动刷新   | 选中时                                     |
| -------------------------- | ---------- | ------------------------------------------ |
| 已启用且有有效原生实例     | 5 分钟     | 展示缓存；过期时刷新；手动刷新始终强制执行 |
| 已启用、无实例、通知已开启 | 5 分钟     | 距上次尝试超过 5 分钟时刷新                |
| 已启用、无实例、通知未开启 | 15 分钟    | 距上次尝试超过 5 分钟时刷新                |
| 未启用                     | 不自动刷新 | 不自动刷新                                 |

按各提供商的上次**刷新尝试**调度，而非定时整批请求。启用状态、实例、通知或凭据变化时重新计算到期时间。保留单飞刷新、失败退避和 120 秒超时。过期阈值采用有效间隔的两倍，即 10 或 30 分钟。两处界面显示实际最后刷新时间。手动刷新立即强制执行；选中后台提供商时立即展示缓存，超过 5 分钟才补刷，避免每次打开 popup 都发请求。启用通知的提供商保持及时评估。

## 视觉与无障碍

沿用现有语义色彩、字体、提供商图标、明暗主题、紧凑密度、本地化及减少动画设置。使用语义按钮和开关，提供明确的焦点与选中状态；摘要同时显示名称和数值，不只依赖颜色。三列有独立标题和滚动区域，键盘焦点不能被遮住。Popup 和设置预览复用同一个数据组件，保证数值、单位和错误状态一致。

## 验收标准

1. 设置在宽窗口显示“列表 + 选中提供商设置 + 实时预览”，窄窗口仍可完整操作。
2. Popup 左侧持续展示全部已启用提供商摘要，右侧随选择切换；点击原生实例选中正确提供商。
3. 新启用提供商默认请求实例；明确关闭的实例重启后仍关闭，提供商继续启用。
4. macOS 和 Windows 不再出现 Quota01 应用级图标；没有提供商实例时离开设置需确认，取消后应用和设置保持打开。
5. 无实例且无通知的提供商降低自动刷新，同时选中补刷、过期状态、通知和手动刷新行为正确。
